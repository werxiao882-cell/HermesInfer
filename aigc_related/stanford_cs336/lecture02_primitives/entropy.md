## Entropy (熵)

在信息论和机器学习中，熵(严格来说是香农熵，Shannon Entropy)是用来衡量一个概率分布的“不确定性”或“信息量”的指标。

你可以从“惊讶程度”来直观理解它。假设有一件事情即将发生：如果这件事发生的概率极低，当它真的发生时，你会感到非常惊讶，这意味着这件事包含了巨大的“信息量”。相反，如果一件事是必然发生的(比如明天太阳依然从东边升起)，它的发生并不会给你带来任何新知识，其信息量就为零。一个系统越混乱、越难以预测，它的熵就越大；一个系统越确定，它的熵就越小。

### 熵的定义与公式拆解

对于一个离散随机变量 $X$ ，假设它有 $n$ 种可能的状态，每种状态发生的概率分布为 $P(x)$ ，那么该变量的熵 $H(X)$ 定义为：

$$H(X) = -\sum_{i=1}^{n} P(x_i) \log P(x_i)$$

我们可以把这个公式拆解为两步简单的逻辑，来理解其背后的先验知识：

1. **计算单点代价**： $-\log P(x_i)$ 代表单一事件 $x_i$ 的信息量(也叫自信息)。对数函数恰好满足“概率越小，信息量越大”的常理。如果在脑海中画一下 $y=-\log(x)$ 在 $(0,1]$ 区间内的图像，你会发现：当 $P(x)$ 趋近于 0 (极小概率事件)时，曲线陡峭上升， $-\log P(x)$ 趋向于正无穷，代表巨大的信息量；当 $P(x)$ 等于 1 (必然事件)时，曲线触底， $-\log(1)=0$ ，代表没有任何新信息。

2. **计算全局期望**： $P(x_i)$ 是该事件发生的真实概率，作为权重去乘以上面的单点信息量，然后再对所有可能的情况求和。

因此，熵 $H(X)$ 本质上就是整个概率分布中所有可能事件信息量的数学期望(Expected Information)。它代表了你在观测结果之前，对这个系统整体的不确定程度。

### 经典的例子：抛硬币

为了加深理解，我们想象抛一枚硬币的场景，并以 2 为底数计算(此时信息量的单位是 bit)：

*   **情况一(绝对公平的硬币)**：正反面出现的概率都是 0.5。代入公式计算：

    $$H(X) = - (0.5 \times \log_2 0.5 + 0.5 \times \log_2 0.5)$$

    因为 $\log_2 0.5 = -1$ ，所以 $H(X) = - (-0.5 - 0.5) = 1$ 。
    
    **结论**：绝对公平硬币的熵为 1bit。这代表系统的不确定性达到了最大值，你需要完整的一位二进制信息才能表达下一次抛硬币的结果。

*   **情况二(严重作弊的硬币)**：假设正面概率是 0.99，反面概率是 0.01。代入公式计算：

    $$H(X) = - (0.99 \times \log_2 0.99 + 0.01 \times \log_2 0.01)$$

    分别计算两个对数值 $\log_2 0.99 \approx -0.0145$ 和 $\log_2 0.01 \approx -6.6439$ ，继续代入得到 $H(X) \approx 0.0808$ 。

    **结论**：严重作弊硬币的熵大约只有 0.0808bit。因为结果几乎是确定的，系统内部包含的不确定性极小。

通过具体的数值对比可以看出，均匀分布产生了最大的熵，而极其倾斜的分布产生的熵极小。

### 为什么熵对模型训练如此重要？

在深度学习的任务中(例如大语言模型的词表概率预测或图像分类)，模型输出的本质就是一个概率分布。在信息论中，熵代表了对一个真实数据分布进行完美编码所需要的理论最小成本(即最短的平均编码长度)。

当我们训练神经网络去逼近真实数据时，我们其实就是在努力消除不确定性，试图让模型的预测分布尽可能贴合真实分布。真实分布的熵，就是我们优化 Loss 时无论如何也无法逾越的理论下界。在模型训练的过程中，随着模型对数据的拟合越来越好，其输出分布的熵也会随之降低。理解了这一点，我们就构建了通往交叉熵和 KL 散度的桥梁。

## KL Divergence (KL 散度)

在理解了熵是如何衡量单一分布的不确定性之后，我们自然会遇到下一个问题：在模型训练中，我们如何衡量模型预测的分布与真实的分布之间有多大差距？这时候就需要引入 KL 散度(Kullback-Leibler Divergence，也叫相对熵)。

### 核心直觉：什么是额外代价？

假设我们有一个真实的概率分布 $P$ (例如数据集中确定的客观标签)，以及一个模型预测的概率分布 $Q$ 。 KL 散度 $D_{KL}(P||Q)$ 衡量的是：如果我们用模型预测的分布 $Q$ 来近似真实的分布 $P$ ，会导致我们损失多少信息，或者说在信息编码上需要付出多少**额外代价**。

### 数学定义与公式推导

KL 散度的数学公式定义为：

$$D_{KL}(P||Q) = \sum_{i=1}^{n} P(x_i) \log \frac{P(x_i)}{Q(x_i)}$$

乍一看这个公式有些复杂，但如果我们结合对数运算法则 $\log(A/B) = \log A - \log B$ ，将对数项拆解开来，其物理意义就变得豁然开朗了：

$$\log \frac{P(x_i)}{Q(x_i)} = (-\log Q(x_i)) - (-\log P(x_i))$$

我们可以清晰地看到这里面的两项：
* **第一项 $-\log Q(x_i)$**：代表我们用错误的分布 $Q$ 去处理事件时，所需要的编码长度(也就是实际付出的代价)。
* **第二项 $-\log P(x_i)$**：代表如果用真实的分布 $P$ 去处理事件时，原本需要的理想编码长度(这正是上一节讲的真实分布的单点熵)。

所以，这两项相减，代表的就是因为我们错用了分布 $Q$ ，导致在单个事件上多花了多少额外代价。公式最外面的求和符号 $\sum P(x_i)$ ，就是把每种可能情况的真实概率，去乘以这个额外代价，求出一个整体的数学期望。算出来的总额外代价期望，就是 KL 散度。

### KL 散度的两大核心性质

在使用 KL 散度时，有两个非常重要的数学性质需要牢记：

1. **非负性**： KL 散度的值永远大于等于 0，即 $D_{KL}(P||Q) \ge 0$ 。从直觉上看，KL 散度衡量的是：真实世界按分布 $P$ 发生，我们却误用分布 $Q$ 去设计编码方案时，平均会**多付出多少信息代价**；非负性正是这句话的数学表达——多付的代价不可能为负，只有 $P$ 与 $Q$ 完全一致时才不必多付。因此，只有当两个分布一模一样时 KL 才等于 0；只要预测与真实存在偏差，就必定存在额外代价。
2. **不对称性**： $D_{KL}(P||Q) \neq D_{KL}(Q||P)$ 。用预测分布近似真实分布的代价，与用真实分布近似预测分布的代价是不同的。这也是为什么在严谨的数学定义中，它被称为“散度”而不是“距离”(因为距离必须满足对称性)。

### 通往交叉熵的终极等式

这是连接理论与工程实践最激动人心的一步。如果我们把上面拆解后的 KL 散度公式在求和符号下完全展开：

$$D_{KL}(P||Q) = \sum_{i=1}^{n} P(x_i)(-\log Q(x_i)) - \sum_{i=1}^{n} P(x_i)(-\log P(x_i))$$

用自然语言翻译这个等式，就是：**KL 散度 = 交叉熵 - 熵**。

等式右边的第一项，正是深度学习中最著名的交叉熵(Cross-Entropy) $H(P,Q)$ 。等式右边的第二项，就是真实分布 $P$ 的熵 $H(P)$ 。我们可以得到核心等式：

$$H(P,Q) = H(P) + D_{KL}(P||Q)$$

在分类任务等大多数深度学习场景中，真实的标签分布 $P$ 是固定的客观事实(比如 One-Hot 编码的标签)。既然 $P$ 是固定的常数分布，那么它的熵 $H(P)$ 也是一个无法改变的常数。因此，当我们想要让模型分布 $Q$ 逼近真实分布 $P$ (即最小化 KL 散度)时，因为真实熵是常数，我们实际上**只需要最小化交叉熵**就可以了。

这就是为什么我们在写训练逻辑时，直接调用交叉熵作为损失函数，而不需要去计算包含常数项的完整 KL 散度。

## Cross Entropy (交叉熵)

终于来到了信息论在深度学习中应用的最核心——交叉熵。有了前面“熵”和“KL 散度”的铺垫，理解交叉熵在分类任务中的底层逻辑将变得水到渠成。

### 理论推导：连接 KL 散度与熵

在上一节的最后，我们推导出了一个极其重要的核心等式：

$$H(P,Q) = H(P) + D_{KL}(P||Q)$$

其中：
* $D_{KL}(P||Q)$ 是 KL 散度(衡量模型分布 $Q$ 与真实分布 $P$ 的差异)。
* $H(P,Q)$ 就是交叉熵。它的完整数学定义为： $H(P,Q) = -\sum_{i=1}^{n} P(x_i) \log Q(x_i)$
* $H(P)$ 是真实分布的熵。

在信息论中，交叉熵衡量的是：如果我们错误地以为系统分布是 $Q$ ，并根据 $Q$ 来对系统进行编码，此时所需要的平均信息量(总代价)。

### 为什么工程实践中只优化交叉熵？

在写模型训练代码时，我们的终极目标是让预测分布 $Q$ 逼近真实分布 $P$ ，也就是最小化 KL 散度。

根据上面的等式做个移项：
$$D_{KL}(P||Q) = H(P,Q) - H(P)$$

在大多数任务中(比如大语言模型的 Next-Token 预测或者图像分类)，真实的标签分布 $P$ 是固定的客观事实(例如图片里是一只猫，这个事实不会变)。既然 $P$ 是固定的常数分布，那么它的熵 $H(P)$ 也是一个无法改变的常数。

因此，最小化 KL 散度在数学推导和梯度更新上，完全等价于最小化交叉熵。因为交叉熵的公式计算起来更简单(省去了算常数 $H(P)$ 的那一步)，它自然就成了优化器进行梯度下降时的首选 Loss 函数。

### 从通用公式到“独热编码” (One-Hot)

在深度学习的分类问题（如 CLIP 或普通分类）中：

*   $P(x)$ (**真实分布**)：通常是一个 **One-Hot 向量**。假设正确类别是第 $k$ 个，那么 $P(x_k) = 1$ ，而其他的 $P(x_{i \neq k}) = 0$ 。
*   $Q(x)$ (**预测分布**)：是模型经过 **Softmax** 层后输出的概率值。

我们将这个特性带入交叉熵公式：

$$H(P, Q) = -(0 \cdot \log Q(x_1) + \dots + 1 \cdot \log Q(x_k) + \dots + 0 \cdot \log Q(x_n))$$

$$H(P, Q) = -\log Q(x_k)$$

**结论**：在单标签分类中，交叉熵损失简化为了：**负的“正确类别所对应的预测概率”的对数**。

### 从概率到 Logits (代码实现的推导)

在 PyTorch 代码中，我们通常不直接对 Softmax 的结果取对数，而是直接操作 **Logits**（模型未归一化的输出值 $z$），原因是为了**数值稳定性**。

假设模型输出的 Logits 为 $z$ ，那么第 $k$ 个类别的概率 $Q(x_k)$ 计算如下：

$$Q(x_k) = \frac{\exp(z_k)}{\sum_j \exp(z_j)}$$

把这个代入我们简化的损失公式：

$$Loss = -\log \left( \frac{\exp(z_k)}{\sum_j \exp(z_j)} \right)$$

利用对数的性质 $\log(\frac{A}{B}) = \log A - \log B$：

$$Loss = -(\log(\exp(z_k)) - \log(\sum_j \exp(z_j)))$$

$$Loss = \log(\sum_j \exp(z_j)) - z_k$$

### PyTorch 代码实现 (手动计算交叉熵)

结合上述公式推导，下面是 PyTorch 中手动实现交叉熵损失的代码示例（带有数值稳定性优化）：

```python
def manual_cross_entropy(logits, targets):
    """
    手动实现交叉熵损失函数。
    CrossEntropyLoss = Softmax + Log + NLLLoss
    或者直接使用公式: loss = -log(exp(x_i) / sum(exp(x_j)))
    为了数值稳定性，通常使用: loss = -x_i + log(sum(exp(x_j)))
    """
    # 1. 为了数值稳定性，减去每行的最大值 (防止 exp 指数爆炸)
    # logits shape: [batch_size, num_classes]
    max_logits = torch.max(logits, dim=1, keepdim=True)[0]
    stable_logits = logits - max_logits
    
    # 2. 计算 Softmax 的分母: sum(exp(logits))
    exp_sum = torch.sum(torch.exp(stable_logits), dim=1)
    
    # 3. 获取正样本对应的 logit 值 (x_i)
    # targets 是 [0, 1, 2] 这种索引
    batch_size = logits.shape[0]
    # 使用 range 配合 targets 索引出对角线上的值（即正样本的 logits）
    target_logits = stable_logits[torch.arange(batch_size), targets]
    
    # 4. 计算每个样本的 loss: -log(exp(x_i) / sum(exp(x_j)))
    # 等价于: -(target_logits - log(exp_sum))
    # 即: log(exp_sum) - target_logits
    sample_losses = torch.log(exp_sum) - target_logits
    
    # 5. 返回平均损失
    return sample_losses.mean()
```

### 梯度视角：为什么不用分类错误率作为 Loss？

既然目的是分类，为什么不直接算分类错误率(比如预测错 10 个， Loss 就是 0.1)？

原因在于梯度下降算法的需要：
1. **平滑可导**：分类错误率是一个阶跃函数，不可导，无法反向传播。而交叉熵函数 $-\log(x)$ 是一条平滑的、处处可导的曲线。
2. **动态惩罚机制**：交叉熵对模型的“过度自信”有极好的惩罚作用。如果模型预测正确类别的概率是 $0.99$ ， $Loss = -\log(0.99)$ 接近 0，梯度很小。如果模型犯了极其离谱的错误(比如给正确类别预测的概率只有 $0.01$ )， $Loss = -\log(0.01)$ 的值会变得非常大，产生一个巨大的 Loss 和强烈的梯度，强迫模型快速纠正错误。

### 进一步对比：为什么大模型不用 MSE 而用交叉熵？

这是一个非常典型的面试问题。既然均方误差(MSE)在回归任务中如此常用，为什么分类任务、以及大语言模型的 Next-Token 预测，要选择交叉熵而不是 MSE？

**理由一：任务本质不匹配——类别没有“距离”概念**

MSE 的核心假设是，预测值和真实值在数轴上有可以度量的几何距离，越接近越好。这在房价预测、温度回归等任务中完全成立。

但在分类任务中，类别本身是离散的、无序的。对于一个词表大小为 50000 的大语言模型，Token ID `256` 和 Token ID `257` 在语义上没有任何“更近”的关系，它们可能一个是“猫”，一个是“椅子”。如果用 MSE 优化，模型会错误地认为预测成 `255` 比预测成 `1000` 惩罚更小，但这两个错误在语义上毫无本质差别。交叉熵则直接作用在概率分布层面，完全绕开了这个问题。

**理由二：梯度行为——Softmax + MSE 会导致梯度消失**

这是最核心的工程原因。我们来对比两种组合在训练中的梯度表达式。

**Softmax + 交叉熵**：这两者联合求导后，梯度有一个极其优雅的闭合形式：

$$\frac{\partial \text{Loss}}{\partial z_i} = Q(x_i) - P(x_i) = \hat{y}_i - y_i$$

梯度就是“预测概率 - 真实概率”，简洁、线性、永远不会饱和。无论模型的输出 Logit 多么极端，梯度信号始终清晰。

**Softmax + MSE**：联合求导后，梯度表达式则变为：

$$\frac{\partial \text{Loss}}{\partial z_i} = \sum_j (\hat{y}_j - y_j) \cdot \hat{y}_j (\delta_{ij} - \hat{y}_i)$$

这个式子不仅计算更复杂，更危险的是，当模型对某个类别的预测概率 $\hat{y}_j$ 趋近于 0 或 1 时，整个梯度式子中 $\hat{y}_j(1-\hat{y}_j)$ 这项会趋向于 0，导致**梯度消失**，使模型陷入“正确了也学不动，错了也纠正不了”的僵局。

**理由三：最大似然估计(MLE)的理论保障**

从概率论的角度来看，选择交叉熵有严格的理论依据。假设我们认为模型输出是对“下一个 Token”这一**类别型随机变量**的预测，那么它自然服从**多项分布(Categorical Distribution)**。对多项分布的参数进行最大似然估计(MLE)，其等价的优化目标正是最小化交叉熵：

$$\text{MLE} \Leftrightarrow \max_\theta \sum_i P(x_i) \log Q_\theta(x_i) \Leftrightarrow \min_\theta H(P, Q_\theta)$$

MSE 对应的隐含假设是输出服从**高斯分布**，这与语言建模任务中“从离散词表中采样”的本质南辕北辙。选用错误的概率假设，会导致优化目标与真实目标不对齐。

**小结**

| 对比维度 | MSE | 交叉熵 |
|:---|:---|:---|
| 适用任务类型 | 连续值回归 | 离散类别预测 |
| 类别关系假设 | 类别间有几何距离 | 类别独立，无序 |
| 与 Softmax 联合梯度 | 复杂，易饱和消失 | 简洁：y_hat - y |
| 概率论理论依据 | 高斯分布的 MLE | 多项分布的 MLE |
