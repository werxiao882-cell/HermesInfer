## 摘要

Emu3 走的是 **GPT 式统一**：把图、视频也离散化成 token，和文字拼成一条序列，用**同一个自回归 Transformer**、**同一个 next-token 交叉熵** 同时做理解和生成，**不用扩散、也不用 ViT+LLM 拼装**。难点在于视觉要先经过 **VQ tokenizer** 压成几千个离散符号，否则像素级自回归算不动；生成就是「续写视觉 token」，理解就是「读入视觉 token 再续写文字」。

---

## 一、要解决什么问题

多模态长期有三套「分裂」：

1. **理解**：ViT/CLIP 提特征 + LLM 推理（LLaVA 系）  
2. **生成**：扩散模型（SD、Sora）  
3. **目标函数**：语言是 CE，图像是噪声预测 / 分数匹配  

Emu3 的命题是：**能不能像大语言模型一样，只押「预测下一个 token」**，把感知和生成都收进一条因果链？  
若成立，好处是架构极简、数据与算力都按 LM 的方式 scale，而不是维护多套系统。

## 二、核心思想：一切皆 token

**一句话**：模态差异在进模型前被抹平，模型里只有「上一个 token → 下一个 token」。

| 步骤 | 思想 |
| :--- | :--- |
| 视觉入口 | 像素 → VQ 离散 token（不是连续 patch 向量） |
| 序列 | 文本 token + 视觉 token + 少量结构符号（起止、分辨率 meta 等）排成文档 |
| 模型 | 单一 decoder-only Transformer（本质仍是 Llama 类 LM，扩了词表） |
| 训练 | 全序列 next-token CE（视觉 loss 可降权，避免压过语言） |
| 生成图/视频 | 自回归「接着写」视觉 token，再 decode 回像素 |
| 理解 | 条件里已有视觉 token，自回归「接着写」答案文本 |

与 ChatGPT 的类比：

- 写字 = 预测下一个字  
- 画图 = 预测下一个「视觉字」（码本里的 id）  
- 读图答题 = 先读入一串视觉字，再预测文字  

**Unified 指什么**：不是「一个 API 能调两种模型」，而是**同一套参数、同一 loss、同一推理循环**处理图文视频。

## 三、Vision Tokenizer 为什么存在

这是 Emu3 里**最该讲清楚**的一块：它不是「又一个 ViT」，而是 **让视觉能进语言模型词表的桥梁**。

### 3.1 它必须完成的三件事

1. **极度压缩**  
   一张图若按像素或稠密 patch 自回归，序列太长。Tokenizer 把 512 量级图像压成 **约几千个** 离散符号，LM 才扛得住。

2. **离散化**  
   LM 的 head 是分类：下一个 token 是词表里的哪一个。视觉必须是 **有限类 id**（VQ 码本，常见 32K 量级），不能是 ℝ^d 里的连续向量。

3. **可逆（生成需要）**  
   理解只要 encode；生成还要 **decode 回图像**。所以用 VQ-VAE 路线：有 encoder、码本、decoder，保证「token 序列 ↔ 像素」大致可逆。  
   简而言之：ViT 特征主要为「看懂」；VQ tokenizer 为「看懂 + 画出来」服务。

### 3.2 论文中的具体设计（§2.2 Vision Tokenizer）

在 **SBER-MoVQGAN** 基础上训练，整体仍是 **VQ-VAE + 码本** 路线；相对原始 MoVQGAN，在 **Encoder / Decoder 各加两层带 3D 卷积核的时间残差块**，使同一套结构能处理视频。

| 项目 | 配置 |
| :--- | :--- |
| 输入 | **512×512** 图像，或 **4×512×512** 视频 clip |
| 输出 | **4096** 个离散 token |
| 码本大小 | **32,768** |
| 时间压缩 | **4×**（任意时间长度可泛化） |
| 空间压缩 | **8×8**（任意空间分辨率可泛化） |
| 训练数据 | LAION-High-Resolution（图）+ InternVid（视频） |
| 训练目标 | L2 + **LPIPS** 感知损失 + **GAN** + **commitment**（端到端） |

流程仍是：**Encoder → 量化查码本 → Decoder 重建**。训练逼码本既能压信息，又能在解码时还原纹理；

与 LM 的衔接不变：码本 id 再映射到扩展词表里的视觉 BPE，供 8B 模型预测。

### 3.3 内部在干什么（思想层面）

- **Encoder**：时空下采样到离散网格（对应上表 4× 时间与 8×8 空间）。  
- **Vector Quantization**：每格在 32K 码本中取最近向量，得到整数 id。  
- **Decoder**：重建像素，约束码本质量。  

两层 id（需区分）：

- **码本 id**：tokenizer 内部，负责图像重建  
- **LM 词表 id**：模型真正预测的对象  

Tokenizer **单独预训练、通常冻结**；8B LM 在其上学「视觉 token 的语法」，就像在学一门新语言的拼写。

### 3.4 与 Qwen-VL 里 ViT 的区别

| 维度 | Emu3 Tokenizer | Qwen-VL ViT |
| :--- | :--- | :--- |
| 输出 | 离散、可生成 | 连续、服务理解 |
| 角色 | 压缩 + 词表化 + 解码 | 语义特征提取 |
| 瓶颈 | 重建糊、码本不够大 | 信息进 LLM 时的损耗与长度 |
| 生成 | 同一套 AR | 另接扩散等 |

**记忆句**：Qwen 把视觉当 **embedding** 喂给 LLM；Emu3 把视觉当 **一串词** 写给 LLM。

## 四、多模态主干（8B LM）

视觉 token 进入模型后，主干与 **Llama-2 类 LLM** 同构；**主要改动是扩大 embedding 层**，以容纳离散视觉 token，其余为成熟 decoder-only 组件组合。

| 组件 | 选择 |
| :--- | :--- |
| 归一化 | **RMSNorm** |
| 注意力 | **GQA**（Grouped Query Attention） |
| 激活 | **SwiGLU** |
| 位置编码 | **RoPE**（旋转位置编码） |
| 其他 | QKV 与线性投影 **去掉 bias**；**dropout 0.1** 提升训练稳定性 |
| 文本分词 | **QwenTokenizer**（多语言，含中英文） |

思想上看：Emu3 没有为 multimodal 再发明一套 Transformer，而是 **「标准 LLM + 扩词表」**；理解与生成共用同一因果栈，差别只在序列里写的是文本 token 还是视觉 token。

## 五、和两条主流路线怎么区分

### 5.1 vs 扩散（SD / Sora）

| | 扩散 | Emu3 |
| :--- | :--- | :--- |
| 生成机制 | 迭代去噪，非因果 | 因果自回归，从左到右/按序 |
| 条件 | 常靠 CLIP/T5 等外接 | 条件写进同一 token 序列（caption 在前） |
| 优势 | 单步质量、成熟生态 | 与 LLM 同构，理解生成一体 |
| 劣势 | 与 LLM 两套栈 | 长序列慢、受 tokenizer 上限约束 |

要点：Sora 学的是噪声分布；Emu3 学的是 token 分布——和 GPT 同一种数学题。

### 5.2 vs 组合式 VLM（LLaVA / Qwen-VL）

| | 组合式 | Emu3 |
| :--- | :--- | :--- |
| 结构 | ViT + 投影 + LLM | Tokenizer + 一个 LLM |
| 视觉进 LLM | 连续特征替换/叠加 | 离散 token 与文字并列 |
| 生成 | 一般不是这条线 | 原生 AR 出图 |
| 工程 | 理解强、动态分辨率成熟 | 思想统一，tokenizer 是单点 |

要点：Qwen-VL 是专家混合；Emu3 是坚持「一个大脑」。

## 六、训练与能力要点

**数据**：高质量图文 + 视频，强过滤（分辨率、美学、字幕、运动），caption 要准——**条件全在文本 token 里**，caption 差则生成/理解都差。

**两阶段上下文**：先图文短上下文学会「词 + 图块」；再加视频、拉长到 128K 级，学时间维 `[EOF]` 与 meta（fps、时长）。

**后训练**：同一基座可偏理解或偏生成微调；生成还可 DPO 对齐人类审美——仍是 token 空间上的偏好优化。

**能力与局限**：

- 论文主张：T2I、VQA、短视频生成均可与专用模型竞争  
- 视频：**因果续帧**（像续写文章），而非扩散式整段去噪  
- 局限：**自回归慢、tokenizer 天花板、高分辨率下 token 数膨胀**

## 七、常见问题

**Emu3 是 unified model 吗？**  
是。统一在 **表示（全离散 token）、模型（单 LM）、目标（next-token CE）**；不是统一在「一个 checkpoint 包办一切任务」——理解/生成仍可能后训练侧重不同。

**为什么还要单独训 tokenizer，不端到端？**  
先保证 **重建可靠** 和 **码本稳定**，否则 LM 在学无意义符号；VQ 训练目标（重建+感知损失）与 LM 的 CE 不同，分开更稳。

**和 Chameleon、LlamaGen 一类有何同异？**  
同属「视觉离散化 + AR」。Emu3 强调 **图+视频同一 tokenizer（3D）**、**大规模原生多模态预训练**，并在论文中论证理解生成可不输扩散/LLaVA 路线。

**主要风险？**  
Tokenizer 信息损失；长视频 token 过多；推理延迟；码本对开放域细节（小字、罕见纹理）可能不如连续 ViT 细腻。

**设计上的关键取舍？**  
在 **压缩率（token 数）** 与 **重建质量** 之间；在 **视觉 CE 权重** 与 **语言能力** 之间；是否值得为架构统一牺牲扩散在生成效率上的优势。

## 附：数据流一览

```
像素
  → [Tokenizer：压缩 + 量化] → 视觉 token 串
  → 与文本、meta 拼成文档式序列
  → [一个 Transformer] 预测下一个 token
  → 若是生成：吐出视觉 token → decode → 像素
  → 若是理解：吐出文本 token → 答案
```

与 Qwen-VL 对照：**前者在 LLM 内融合连续视觉；后者在进 LLM 前把视觉写成字。**
